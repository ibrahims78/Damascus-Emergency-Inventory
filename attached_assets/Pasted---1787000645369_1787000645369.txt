
نعم، وأرى أن تطبيق الميزة على التجهيزات والعهد معاً هو الحل الأكثر احترافية، لكن مع فصل واضح بينهما:

أولاً: بطاقة التجهيز
عند الضغط على اسم التجهيز تظهر بطاقة تحتوي على:

اسم التجهيز ونوعه وموديله.
الرقم التسلسلي.
الكمية الإجمالية والمتاحة.
الحالة: جيد، صيانة، معطل، مستهلك، يحتاج فحص.
الحائز الحالي.
الموقع.
بيانات الصيانة.
الملاحظات.
سجل زمني لكل العمليات:
إدخال.
تسليم عهدة.
إعادة عهدة.
تلف.
مرتجع مركزي.
تعديل أو تسوية.
أرقام المستندات والتواريخ والكميات والمستخدم المنفذ.
رابط مباشر إلى العهد المرتبطة بهذا التجهيز.
ثانياً: بطاقة العهدة
العهدة ليست مجرد حركة على التجهيز، بل هي سجل مستقل له دورة حياة. لذلك تكون لها بطاقة منفصلة تعرض:

رقم العهدة.
اسم التجهيز ورقمه التسلسلي.
اسم الحائز.
الجهة أو الشخص المستلم.
الكمية المسلّمة.
الكمية المعادة.
الكمية المتبقية.
تاريخ التسليم.
تاريخ الإعادة.
موقع العهدة.
رقم مذكرة التسليم.
الحالة:
مفتوحة.
معادة جزئياً.
معادة بالكامل.
تالفة.
مغلقة.
مدة بقاء العهدة.
هل العهدة متأخرة أم لا.
سجل تفصيلي:
إنشاء العهدة.
إعادة جزئية.
إعادة كاملة.
تسجيل تلف.
تغيير الحالة.
بيانات الفحص عند الإعادة.
زر طباعة سند التسليم أو الإعادة.
الشكل الأفضل للربط
يكون التنقل متبادلاً:

التجهيز
  └── العهد المرتبطة به
        └── بطاقة العهدة
              └── سجل التسليم والإعادة والتلف

ومن بطاقة العهدة يمكن الرجوع إلى بطاقة التجهيز، ومن بطاقة التجهيز يمكن فتح جميع العهد المرتبطة به.

المسارات المقترحة
/equipment/:id

بطاقة التجهيز وسجل حركاته.

/custodies/:id

بطاقة العهدة وسجل دورة حياتها.

والـ API المقترح:

GET /api/equipment/:id/history
GET /api/custodies/:id
GET /api/custodies/:id/history

الصلاحيات
viewer: عرض البطاقات والسجلات فقط.
warehouse_manager: تسجيل التسليم والإعادة والتلف حسب الصلاحية.
admin: إدارة كاملة وتعديل وإلغاء وإظهار سجل التدقيق.
رأيي النهائي
الأفضل عدم وضع كل التفاصيل في صفحة واحدة. التصميم المهني هو:

بطاقة مستقلة للتجهيز.
بطاقة مستقلة لكل عهدة.
ربط مباشر بين التجهيز والعهد.
سجل زمني غير قابل للتعديل.
أرقام مستندات واضحة.
حالات وألوان تنبيه للعهد المتأخرة أو التالفة.
إمكانية الطباعة والتصدير.
حالياً المشروع يحتوي على قائمة للعهد ومسار API يعرض العهد المفتوحة، لكنه لا يحتوي بعد على بطاقة تفصيلية مستقلة للعهد أو بطاقة حركة تفصيلية للتجهيزات.
